# MLB The Show 26 (`0100AA7024094000`)

<!-- PEANUTS: a Peanuts Native profile and note (Banana Native has none for this title). -->

Update 1.0.19 (v1245184) on base v65536. SDK 19.3.11. San Diego Studio's own engine with NVN graphics. Modules `main` and `sdk` only: no `subsdk`, and `main` imports `nn::ro` but the RomFS holds no `.nro` or `.nrr` files.

**Status (current): provisional profile; the first boot stopped in `nninitStartup` (resolved by `mem_used`, not yet rerun).** The survey, the provisional profile, the shader split and the pack ran on a PC (Linux under WSL) from a `.nup` of the merged base and update; the test app came from `.github/workflows/test-apk.yml`. The aim is the offline modes (Road to the Show, exhibition); the online modes need Sony's servers and are out of scope. The game imports `nn::socket`, `nn::ec`, `nn::friends`, `nn::account` and `nn::nifm` for them.

## Files and shaders

- RomFS: 86,057 files, 35.20 GB. Platform folders `NSW/`, `CROSS/`, `AND/`, `PS4/`, `FLUX/` at the top. Most files are `.tex` (38,014) and `.mod` (25,940).
- **Shaders: GLSLC outputs in `.fxbnvn` files.** `NSW/SHADERS` holds 456 `.fxbnvn` files (161.7 MB, 56 bytes to 2.1 MB). Each starts with `FXB\0`, then its own length and a header length; inside are whole GLSLC outputs (magic `0x19866891`), each with one control section (`0x98761234`, 0x880 bytes) and its code area right after it. 7,720 outputs over all files (7,234 graphics, 486 compute), nothing compressed and no BNSH. 3-file banks of 56 bytes hold no shader. The survey's note ("no BNSH / BAHS at the top level … must be located first") does not count GLSLC outputs; `shader_split.py` reads them through its loose-file GLSLC path (`scan_whole` → `glslc_shaders`) with no new reader. `dm/tools/fxbnvn_probe.py` prints this structure from a `.nup` without writing game data.
- `shader_split.py` found 3,445 shaders: 244 compute, 1,757 pixel, 1,444 vertex, all from `nsw` (the 7,720 outputs repeat across banks). 5,776 variation pairs, 244 compute answer rows, no `[RED]` line. Single-stage programs: the 1,444 vertex shaders are paired with a cover of 4 pixel shaders.

## Memory

- Modules: 0x5a00000 (90 MB) after the rewrite. With the default 64 MB of used memory, `main` asked for a 0xc9400000 heap (pool − 64 MB) and `SetHeapSize` refused it. With `mem_used 0x6000000` it asks for 0xc7500000 (3.11 GB). Not measured in play yet.

## Found on this game

- **Heap sized from the application pool less used memory (resolved).** First boot on an AYN Thor (system driver and Turnip Gen8 V39, three runs): `[mem] SetHeapSize 0xc9400000 + modules 0x5a00000 > app pool 0xcd500000 (used memory reported 0x4000000 + bss 0)`, then `nn::diag abort: Result 0x1003` at `main+0x5b1b60` in `nninitStartup`, before any graphics. Fixed by `mem_used 0x6000000`. [Heap sized from the application pool less used memory](../../docs/reference/memory.md#heap-sized-from-the-application-pool-less-used-memory)

## Open

- SDK 19 (the survey's note: NVN object sizes and service layouts differ by SDK); other SDK 19 profiles exist ([OCTOPATH TRAVELER 0](../01005270232F2000/README.md)), so check against them first at bring-up.
- **Opening video: nsd (current).** With `mem_used` the game reaches `nnMain`, loads its shaders and presents at 60 fps on both drivers, then at `ATT_SCREEN: FMV player init` connects to nsd:a and nsd:u itself and aborts (`Result 0xe8d`, `sdk+0x3f4cfc`, in `nn::nsd::GetApplicationServerEnvironmentType`, called from `main+0x152ab7c`). `main` imports no symbol of that name (its only nsd import is `ResolveEx`), so the host's new answer for it (`hle_offline.c`, retail 0) takes effect only if the call goes through a relocation; not yet rerun.
- Under Sudachi on Android with Turnip, generated players' faces draw black and some limbs draw in solid red, green, blue or white; worth comparing once this profile draws frames.
